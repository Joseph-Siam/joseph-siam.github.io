LLM Prompt-Injection Guard

Can a middleware defence spot malicious instructions before they influence a simulated chatbot?

My contributionSecurity testing & evaluationTeam-built working prototype
The context

A team-built Python / FastAPI prototype that detects and blocks prompt-injection attempts in direct user input and untrusted retrieved content. Testing runs against a simulated chatbot, not a production LLM service.

What I work on
  • Running teammate-prepared CSV attack cases, including multilingual and multi-turn scenarios.
  • Evaluating detection, risk-based responses and model-output checks.
  • Reviewing audit logs and dashboard results, and telling the team where it’s weak.
What it shows

Security evaluation as a loop: define test scenarios, observe behaviour, document gaps, retest after changes. No detection-rate or production-security claim is made here until I have results to back it.
